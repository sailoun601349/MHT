# 猕猴桃订单管理系统 — 项目概述

## 1. 项目背景

个人猕猴桃销售场景，需要一套轻量级的在线下单与订单管理系统。
服务器配置：4 核 4GB 内存，要求资源占用低、维护简单。

## 2. 核心需求

### 2.1 普通用户端（手机优先）

| 功能 | 说明 |
|---|---|
| 进入下单 | 输入手机号即可进入下单页面 |
| 查询订单 | 输入手机号 + 查询码进入订单详情 |
| 提交订单 | 填写收货信息、选择规格、数量，自动生成费用 |
| 获取查询码 | 提交后显示查询码（手机号 + 全局三位顺序号），用于后续查询 |

### 2.2 管理员端（手机 + 电脑）

| 功能 | 说明 |
|---|---|
| 登录 | 管理员手机号 + 登录密码 |
| 订单列表 | 查看所有订单，支持状态筛选 |
| 发货操作 | 上传快递面单照片、输入快递公司 + 单号 |
| OCR 识别（可选） | 后续接入第三方 OCR 自动识别快递单号 |

### 2.3 查询码规则

- **全局递增**：系统所有订单共用一个顺序号，从 001 开始
- **格式**：手机号 + 顺序号，如 `13800000001 + 001`
- **一码多址**：一次提交多个地址生成同一查询码（组码），组内每条地址为一条订单（`sub_no` 1..N）；唯一性为 `(phone, query_code, sub_no)`
- **超过 999**：自然扩展为 4 位、5 位，不截断

## 3. 非功能性需求

| 维度 | 要求 |
|---|---|
| 性能 | 4C4G 服务器轻松运行，内存 < 1GB |
| 适配 | 手机端为主，管理员端兼容电脑 |
| 安全 | 管理员密码哈希存储、手机号格式校验、频率限制 |
| 部署 | Docker Compose 或 systemd 直接部署 |
| 备份 | 每日自动备份数据库 + 上传文件 |
| 维护 | 单体应用，无复杂依赖 |

## 4. 技术选型（已确认）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Flask (Python 3.10+) | 轻量、成熟、生态丰富 |
| 数据库 | SQLite | 单文件、零配置、个人订单量足够 |
| 前端 | Bootstrap 5 + Jinja2 模板 | 响应式、无需前端构建 |
| 部署 | Gunicorn + Nginx (或 Caddy) | 稳定、HTTPS 方便 |
| 图片存储 | 本地文件系统 | 简单直接 |

## 5. 不在本期范围

- 在线支付（微信/支付宝）
- 短信通知
- 微信小程序
- 多级权限扩展（本期仅「超级管理员」与「普通管理员」两级）
- 本地 OCR 部署（后续可接入第三方 API）
