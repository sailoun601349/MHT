# 规格与价格管理（含「规格 × 适用管理员」）— 需求梳理

> 状态：决策锁定（2026-09-04，8 项决策已确认）
> 前置：多管理员体系已上线（`docs/09/10`）；规格当前仍写死在 `app/config.py` 的 `SPECS`，全站共用一份。
> 关联 UI：下单页规格的展示样式遵循 `docs/11-ui-design-spec.md` 另行设计，本期只定数据、规则与接口。

---

## 1. 现状与问题

- **现状**：规格（名称 + 单价）在 `app/config.py:SPECS` 静态定义（5斤装 50 元 / 10斤装 100 元）；下单页 radio 直接渲染配置；下单时 `find_spec` 从 config 按「名称」取价防篡改。
- **问题**：
  1. 规格改价必须改代码重启，超管/管理员无法自助维护；
  2. 全站共用一份规格，无法实现「不同分销管理员卖不同规格/价目」；
  3. 无法回答「这个规格是谁建的、开放给了哪些管理员」。

## 2. 目标 / 非目标

### 目标
1. 规格与价格数据库化，超管与管理员均可自助维护（新增 / 改价 / 下架 / 删除）。
2. 引入「规格 × 适用管理员」关系：顾客下单页只展示其归属管理员适用的规格。
3. 内置 5斤装/10斤装保留系统语义：**每个管理员默认存在**（保底至少 2 个规格）、不可改名、不可删除，价格 ¥50/¥100 **完全锁定**。
4. 权限清晰：创建者天然适用自己的规格且不可被移除；超管统一管理全局适用关系。

### 非目标（本期不做）
- 不做「同一规格按管理员独立定价」（价格跟随规格记录，全局一份）。
- 不做规格排序、套餐/组合、库存、优惠、规格图等电商复杂能力。
- 不做下单页规格的 UI 视觉设计（交 UI 规范后续迭代）。

## 3. 核心概念（用户已确认）

| 概念 | 规则 |
|---|---|
| 内置规格 | id=1 `5斤装` = ¥50、id=2 `10斤装` = ¥100。**名称描述不可修改、不可删除**；**价格 ¥50/¥100 完全锁定，任何人（含超管）不可改** |
| 自定义规格 | 超管或任意管理员均可创建；名称允许中/英文、字母、数字；**允许与既有规格重名**（各自独立记录，按 id 区分） |
| 价格 | 跟随「规格记录」本身，**全局一份**；自定义规格改价对所有适用它的管理员下单同步生效；内置价格锁定除外 |
| 适用关系 | 规格「适用哪些管理员」，决定该管理员下单页能看到哪些规格 |
| 创建者适用 | 创建者**默认适用自己的规格**；超管也无法把创建者从该规格移除，只能删除整个规格 |
| 超管分配 | 超管可给任意自定义规格**增补**适用管理员；可调整内置规格的适用范围（增删均可，但不能删除内置本身） |
| 内置默认适用 | 内置 5斤装/10斤装**每个管理员默认存在**（老管理员上线即有货可卖；新建管理员时自动同步），**确保每个管理员至少有 2 个可卖规格** |
| 数量上限 | **创建 ≠ 适用**，口径：创建配额不含内置 2 个 —— 超管名下可建自定义规格 ≤ 20、普通管理员名下可建 ≤ 10；适用上限含内置 —— 任一管理员「适用」的规格合计 ≤ 20（内置 2 + 他人开放 + 自己创建） |
| 下架 / 删除 | 自定义规格可**下架**（下单页隐藏、不适用新单、可重新上架，适用关系保留）也可**删除**（物理删记录 + 移除适用关系）。历史订单不受影响（订单存名称/单价快照） |
| 名称格式 | 必须含「数字+斤」段（斤紧跟数字，如 `翠香3斤` `5斤小桃` `徐香5斤礼盒装`）；其余仅中英文、字母、数字；长度 ≤ 10 个汉字等宽（半角 2 字符 ≈ 1 汉字，即显示宽度 ≤ 20 半角） |

## 4. 权限矩阵

| 操作 | 超级管理员 | 普通管理员 |
|---|---|---|
| 查看规格 | 全部规格（含所有管理员创建） | 自己创建的 + 适用于自己的 |
| 创建自定义规格 | ✅ | ✅（默认仅自己适用） |
| 改内置（5斤/10斤）价格 | ❌ 完全锁定（¥50/¥100 任何人不可改） | ❌ |
| 改自己创建规格的价格 | ✅ | ✅ |
| 改他人创建的规格价格 | ✅ | ❌ |
| 增补规格的适用管理员 | ✅（对任意规格） | ❌ |
| 移除适用管理员 | 内置：任意；自定义：**不可移除创建者** | ❌ |
| 下架 / 上架 | 任意自定义规格 | 仅自己创建的 |
| 删除 | 任意自定义规格（含管理员建的） | 仅自己创建的 |
| 内置规格改名 / 删除 | ❌ 不可 | ❌ 不可 |

## 5. 数据模型（草案）

### 5.1 `specs`（商品规格）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Integer PK | 规格身份（下单/计价以 id 为准，名称可重名不作为唯一键） |
| name | String(50) | 规格名（如 `翠香3斤`）；格式校验见 §3 |
| price_fen | Integer | 单价（分）；内置固定 5000 / 10000，**改价接口对内置拒绝**；自定义由创建者/超管维护 |
| is_builtin | Boolean | 是否内置（5斤装/10斤装）；内置 = 名称/价格锁定 + 全管理员默认适用 |
| is_active | Boolean | 启用 / 下架，默认 True |
| created_by_admin_id | Integer FK | 创建者；内置规格指向超管 |
| created_at / updated_at | String | — |

### 5.2 `spec_admins`（适用关系，多对多）

| 字段 | 说明 |
|---|---|
| spec_id + admin_id | 联合主键；一条记录 = 该规格对该管理员可见可售 |
| created_at | — |

约束：
- 创建者与自己的规格必有一条适用记录，**删除规格前不可移除**；
- 内置规格 seed 时为所有启用中的管理员各插入一条（新管理员创建时同步插入）。

### 5.3 `orders` 增量

| 字段 | 说明 |
|---|---|
| spec_id | 可空列，落库快照记录下单时的规格 id，便于审计与追溯（`spec_name`/`spec_price` 快照保留） |

### 5.4 迁移（v6）与 seed

- schema 迁移版本 **v6**：建 `specs` + `spec_admins`；`orders` 加可空 `spec_id` 快照列（不加 FK / 关系约束）；
- **内置 seed 在启动 `ensure_spec_defaults` 执行（不在迁移内）**：因迁移时超管可能尚不存在；
  启动顺序 `db.create_all → run_schema_migrations → _seed(超管) → ensure_spec_defaults`；
- seed 幂等可反复跑：`5斤装` = 5000 分、`10斤装` = 10000 分，`created_by` = 超管，`is_builtin = True`；
- 为所有启用中的管理员补内置两条适用记录（新建管理员时由 `sync_builtin_for_admin` 自动同步）；
- 历史订单无需迁移（名称/单价已是快照，`spec_id` 留空）。

## 6. 下单链路改动

```
顾客打开 /<短码>（或根路径 /）
  → 解析归属 owner（沿用 resolve_order_owner，下单页渲染前提前解析一次）
  → 下单页仅列出 owner「适用且启用」的规格（名称 + ¥价格）
  → 顾客选择规格（radio/胶囊等 UI 样式另定），提交时携带 spec_id
  → 服务端按 spec_id 校验：该规格必须属于 owner 适用范围且启用
  → 价格以规格记录当前 price_fen 为准（防前端篡改，沿用现状服务端计价）
  → 落库：spec_id + spec_name/spec_price 快照（分）
```

> 关键变化：**按 spec_id 而非名称取价**。因允许重名，名称不再是可靠键；下单表单需携带隐藏的 `spec_id`，服务端按 id 查规格并校验「适用 + 启用」。

## 7. 页面与入口（管理端）

| 角色 | 入口 | 内容 |
|---|---|---|
| 超管 | 导航新增「规格管理」 | 全部规格表：名称、价格、创建者、状态、适用管理员（勾选维护）、操作（改价 / 下架上架 / 删除）。内置行：名称只读、无删除 |
| 普通管理员 | 导航新增「规格」 | 两个区块：「我创建的」（可改价 / 下架 / 删除 / 新增）；「我适用的」（只读展示，含内置与他人开放给我的） |
| 顾客 | 下单页 | 展示归属管理员适用且启用的规格，UI 样式后续按 `docs/11` 设计 |

## 8. 名称校验（需求级规则 + 参考正则）

- 必须包含「数字 + 斤」段，如 `3斤`、`5斤`、`10斤`；数字前后均可带文字。
- 允许字符：汉字、英文字母、数字；不允许其它符号（空格、标点等）。
- 长度：显示宽度 ≤ 10 汉字（半角 2 字符折 1 汉字）。
- 参考正则：`^[\u4e00-\u9fa5a-zA-Z0-9]*\d+斤[\u4e00-\u9fa5a-zA-Z0-9]*$`
  - 合法：`翠香3斤`、`5斤小桃`、`徐香5斤礼盒装`、`5斤装`
  - 非法：`3斤2`（斤后又数字）、`3kg`（无斤）、`精品装`（无数字斤）、`A-5斤`（含符号）

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|

| POST | `/admin/specs/create` | 新建规格（name + 价格） | 超管 / 管理员 |
| POST | `/admin/specs/<id>/price` | 改价 | 权限矩阵 |
| POST | `/admin/specs/<id>/toggle` | 下架 / 上架 | 权限矩阵 |

| POST | `/order/create` | 按 spec_id 校验适用 + 服务端计价 | 公开 |

## 10. 已确认决策（2026-09-04 锁定）

| # | 决策点 | 结论 |
|---|---|---|
| ① | 内置 5斤/10斤 的价格 | **¥50 / ¥100 完全锁定，任何人（含超管）不可改**（2026-09-04 追加确认，覆盖早前「仅超管可改」口径） |
| ② | 超管创建的自定义规格默认适用谁 | 仅超管自己；再手动勾选分配给其他管理员 |
| ③ | 管理员能否「拒绝」他人开放给自己的规格 | **不能**；适用关系由超管统一管理，管理员视角只读展示 |
| ④ | 价格输入范围 | 0 < 价格 ≤ 9999 元，两位小数；内部存分 |
| ⑤ | 下架是否保留适用关系 | **保留**；重新上架即恢复可见，删除才清适用关系 |
| ⑥ | 同名规格下单页如何展示 | **允许重名**；下单页按价格区分展示；若「名称与价格均相同」，交由人为处理（删除其一或下架其一）；UI 样式后续设计 |
| ⑦ | 数量上限 | **创建配额（不含内置 2 个）**：超管名下可建自定义规格 ≤ 20、普通管理员名下可建 ≤ 10；**适用上限（含内置）**：任一管理员适用的规格合计 ≤ 20 |
